A. ROOT CAUSE
   Fixture construction (directive option *a*).  The shared test helper
   `_seed_archive` (tests/test_historical_context.py, ~line 51) generates
   game ids WITHOUT the competition dimension:

       gid = f"A{i // 2:04d}"          # 2 observations per game

   The failing test seeds TWO competitions through this helper:
     _seed_archive(c, "betual-nba", ...)   -> games A0000..A0019
     _seed_archive(c, "betual-kbl", ...)   -> games A0000..A0019  (SAME ids)
   The KBL seeding then re-registers those same game ids in the competition
   ledger with INSERT OR REPLACE (helper, ~line 84), clobbering the NBA
   mapping.  Result, dumped from a byte-exact reproduction of the fixture:

     ledger competition counts after both seeds: [('betual-kbl', 20)]
     distinct projection game ids: 20   (40 were seeded, two seeds collided)
     projections rows: BETUAL_NBA = 80  (both competitions share rows' gids)

   refresh_stats then resolves ALL 80 rows through the ledger to kbl and
   writes exactly one cache key:

     refresh_stats -> {'keys': 1}
     historical_context_cache -> ('BETUAL|betual-kbl|Q4|P090', n=160, ...)
     (n=160 = both 40-row seeds merged into one key)

   context_for('LIVE3') correctly resolves provider=BETUAL,
   competition=betual-nba (via register_game_competition from the games
   table, which is NOT clobbered) and computes key
   BETUAL|betual-nba|Q4|P090 — but its prior-only benchmark population
   (ledger join, competition='betual-nba') is now EMPTY (n=0), so the engine
   reports no_mature_historical_context and the NBA key never exists in the
   cache.  The assertion
       assert "BETUAL|betual-nba|Q4|P090" in keys
   fails exactly as observed.  The application code path behaved correctly
   at every step given the (corrupt) fixture data.

   Ruled out: (b) insufficient priors — see D; (c) stale cache — the test
   builds fresh in-memory DBs; (d) ledger mapping logic — production ledger
   is correct (see E), the fixture merely overwrote its own rows;
   (e) progress-bucket classification — 93.75 -> P090 verified in both
   fixture and production; (f) N>=30 — 40 obs seeded, gate satisfied (the
   observed n=160 proves the gate was not the blocker); (g) same-game
   exclusion — irrelevant to the cache key set; (h) prior-only cutoff —
   LIVE3's captured_at (2026-02-01) is strictly after all seeded rows;
   (i) no other implementation issue found.
