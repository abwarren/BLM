LOGIC CHANGED (exact, by directive section)
════════════════════════════════════════════════════════════════════
§1/§2/§4  AUTHORITATIVE STATE — api.py
  _ws_game_state(): freshest VALIDATED WS frame for a game from
  market_observations (MatchTotal rows with period_label+clock+both
  scores; line-only rows skipped). Nothing fabricated.
  _state_is_regression(): monotonicity guard — rejects candidates that
  move the accepted state backwards (quarter decrease = Q4→Q3; same-
  quarter clock increase = newer clock→older clock; 00:00 sentinel is a
  period END, never a regression). Only complete states are compared;
  missing fields never called a regression.
  _authoritative_game_state(): selection order —
    1. newest COMPLETE DOM frame while fresh (age <= WS_STATE_FALLBACK_S)
    2. otherwise freshest validated WS frame (unless it would regress)
    3. otherwise newest DOM frame of any shape (legacy degraded path)
  A NULL-score/NULL-quarter snapshot can NEVER replace a newer complete
  state; a stale DOM state no longer freezes the display when a healthy
  WS frame exists. Unvalidated DOM fields are never merged into WS state.
§5  FRESHNESS METADATA — api.py
  Every served game carries game_state_freshness = {source
  (ws|dom), state_observed_at, state_age_seconds, source_observed_at}.
  The API generation timestamp is never used as a freshness proxy.
  /api/v4/status also exposes set-wide game_state_freshness percentiles.
§6  ALERT SAFETY — api.py
  New constant ALERT_MAX_STATE_AGE_S = 300.0 (documented market-
  freshness limit). _alert_gate() fails closed with reason stale_state
  when the accepted state age is missing or > bound. The gate is folded
  into the served under_alert_eligibility verdict AFTER the market gate
  (can only tighten). No remaining-minute or pace compensation.
§7  GAME-FINISHED RECONCILIATION — server.py
  New background reconciler thread (60s cadence, independent of the
  scorecard workload): flips pending checkpoints to game_finished the
  moment an authoritative final exists, and exposes a freshness probe.
  No second collector created; scorecard untouched.
§8  DASHBOARD — index.html + dashboard.js
  Header now shows TWO separate clocks: API response age (existing
  FRESH/STALE pill) AND game-state age (new STATE pill fed by
  game_state_freshness percentiles). A recent JSON carrying old game
  states can no longer read as all-fresh.
§9  ACTIVE ALERTS — server.py + dashboard.js
  Backend: reconciler flips the authoritative verdict promptly when the
  game finishes. Frontend: reconcileUnderAlerts closes ACTIVE records
  whose game the payload's authoritative state marks over (status ended
  / live=false / terminal reason) and never resurrects them
  (gameOverIds gate, close-only). Reconciled with requirement N
  (2026-09-14): this is LIFECYCLE reconciliation consuming only the
  backend's own state verdict — not the second ELIGIBILITY decision N
  forbids; N's core case (gate-ineligible but game still live) still
  displays, now pinned by the split N/N2 tests.
